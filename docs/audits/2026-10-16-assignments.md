# Assignments audit — student and teacher

Date: 2026-10-16. Mode: Operate. Scope: the dedicated student and teacher Assignments workspaces, teacher results/analysis/settings, question inspection, student readiness dialog, and shared navigation. Audit only; no application fixes applied.

## Implementation integrity verdict

**Fail on interaction and state consistency; the visual identity is coherent.** Both roles use recognizable classroom typography, status stamps, the rail/sidebar workspace, and reusable components. However, the teacher tabs advertise keyboard and panel relationships that are not implemented, the readiness dialog bypasses the existing dialog manager, and status sorting uses different values from the rendered labels. These are verified implementation problems, not a request to redesign the classroom identity.

The Impeccable detector produced five warnings. None establishes an additional defect in the audited views after contextual review:

- Three `gray-on-color` warnings at teacher view lines 754, 761, and 881 combine mutually exclusive Alpine class branches. The actual colored states use white or emerald text; those reported combinations do not occur.
- The `side-tab` warning at workspace CSS line 955 belongs to `.pinned-note-card`, which is not rendered by these Assignments views.
- The `overused-font` warning at workspace CSS line 96 conflicts with the explicitly approved classroom font exception in `DESIGN.md`. Preserve that decision.

## P1 — major

### 1. Teacher tabs are unreachable with normal keyboard navigation

**Location:** [tab-bar.blade.php:9](D:/Projects/php/digital-sat/resources/views/components/shell/tab-bar.blade.php:9); [teacher show:169](D:/Projects/php/digital-sat/resources/views/teacher/assignments/show.blade.php:169), also panels at 223 and 963. **Category:** Accessibility.

Only the selected tab has `tabindex="0"`; the other two have `-1`. There are no arrow/Home/End handlers. In the live browser, ArrowRight on Student results did nothing and Tab went straight to Search students. A keyboard user cannot reach Analysis or Settings through the tab control. All three `aria-controls` targets are also absent; panels have no matching IDs or tabpanel relationships.

**Standard:** WCAG 2.1.1 Keyboard and 4.1.2 Name, Role, Value. **Recommendation:** implement the complete keyboard tab pattern and matching named panels, or use ordinary keyboard-focusable navigation buttons without roving tabindex. Validate the initial `tab` query against allowed keys. **Command:** `$impeccable harden`.

### 2. Student readiness dialog leaves focus behind its modal overlay

**Location:** [ready-modal.blade.php:15](D:/Projects/php/digital-sat/resources/views/components/ui/ready-modal.blade.php:15); [dialog-manager.js:109](D:/Projects/php/digital-sat/resources/js/ui/dialog-manager.js:109). **Category:** Accessibility.

Clicking Start attempt opens a real `aria-modal` dialog, but focus stays on the background launcher. Tab first visits background content, then enters the dialog and eventually exits it. The page is not inert and the dialog has no accessible name. The component listens to `open-ready-modal`, whereas the shared manager only handles the standard modal/offcanvas events.

**Standard:** WCAG 2.4.3 Focus Order and 4.1.2. **Recommendation:** give the title an ID, connect `aria-labelledby`, and use the managed dialog lifecycle for initial focus, containment, background inertness, and focus restoration on every close path. **Command:** `$impeccable harden`.

### 3. Closed phone navigation remains in the keyboard focus order

**Location:** [classroom-nav.js:14](D:/Projects/php/digital-sat/resources/js/classroom-nav.js:14); [shell.css:618](D:/Projects/php/digital-sat/resources/css/shell.css:618); [workspace CSS:1842](D:/Projects/php/digital-sat/resources/css/classroom-workspace.css:1842). **Category:** Accessibility / Responsive.

The closed rail and assignment list are translated offscreen without becoming inert. On both roles at 390 px, pressing Tab after Open menu focused the hidden logo and navigation links at negative horizontal coordinates. Users lose visible focus before reaching the assignment content. Opening/closing also lacks a managed focus handoff.

**Standard:** WCAG 2.4.3 and 2.4.7 Focus Visible. **Recommendation:** make the closed drawer inert, manage focus when opened, prevent focus escaping behind an open overlay, and restore the toggle on close; account for desktop breakpoint changes. **Command:** `$impeccable harden`.

### 4. Repeated status and helper text fail text contrast

**Location:** [workspace CSS:634](D:/Projects/php/digital-sat/resources/css/classroom-workspace.css:634), [workspace CSS:1457](D:/Projects/php/digital-sat/resources/css/classroom-workspace.css:1457); [teacher show:998](D:/Projects/php/digital-sat/resources/views/teacher/assignments/show.blade.php:998), also 1013, 1021, 1036. **Category:** Accessibility / Theming.

### 5. Schedule labels are disconnected from the visible date fields

**Location:** [app.js:54](D:/Projects/php/digital-sat/resources/js/app.js:54); [teacher show:995](D:/Projects/php/digital-sat/resources/views/teacher/assignments/show.blade.php:995), also 1018. **Category:** Accessibility.

Assistive technology and speech input cannot reliably identify the intended schedule field.

**Standard:** WCAG 1.3.1 Info and Relationships and 2.5.3 Label in Name. **Recommendation:** connect each visible alternate input to its real label, preserving the hidden submission field and programmatic label activation. Associate explanatory/error text as well. **Command:** `$impeccable harden`.

### 6. Schedule Clear buttons fail minimum target size

**Location:** [teacher show:996](D:/Projects/php/digital-sat/resources/views/teacher/assignments/show.blade.php:996), also 1019. **Category:** Accessibility / Responsive.

**Standard:** WCAG 2.5.8 Target Size (Minimum), 24×24 CSS px or qualifying spacing; 44×44 is the stronger touch comfort target, not the AA minimum. **Recommendation:** enlarge the actual hit area while keeping the compact visual treatment. **Command:** `$impeccable adapt`.

**Standard:** functional filtering correctness. **Recommendation:** navigate/refetch when class changes, or deliberately load the full authorized dataset before filtering locally. **Command:** `$impeccable harden`.

### 12. Status sorting does not match the visible status labels

**Location:** [report service:116](D:/Projects/php/digital-sat/app/Services/AssignmentReportService.php:116), also 172; [results view:86](D:/Projects/php/digital-sat/resources/views/livewire/teacher/assignment-student-results.blade.php:86). **Category:** Implementation Integrity / Accessibility.

Sort headers also omit `aria-sort`, so direction is not exposed as table-header state.

**Standard:** sort correctness; WCAG 1.3.1 for programmatic sort state. **Recommendation:** choose and name the column's status concept explicitly, share that value between sorting/rendering, and expose ascending/descending on the active header. **Command:** `$impeccable harden`.

## Patterns and positive findings

The recurring failures are incomplete behavior around otherwise reusable components: visual tabs without keyboard behavior, a modal outside the shared lifecycle, transformed navigation without focus state, and replacement inputs without replacement labels. Status is also recomputed separately for display, sorting, and color.

Maintain these strengths:

- Clear shared workspace structure and documented classroom identity; no speculative redesign is needed.
- Search fields generally have accessible names, navigation links use real anchors, and the rail exposes the current page.
- Status stamps include readable labels and dots rather than relying on color alone.
- Teacher results use server-side search, sorting, pagination, and debouncing. Query construction batches attempt loading rather than fetching each row independently.
- The shared question-inspection modal already uses the managed dialog events; extend that existing pattern to readiness.
- Phone table touch panning works. Content panes avoid document-wide horizontal overflow at the tested phone width.
- Reduced-motion handling deliberately removes panel/spatial motion while retaining useful color/opacity feedback.
- All eight initial role/tab/viewport loads returned HTTP 200 with no uncaught browser JavaScript errors.
